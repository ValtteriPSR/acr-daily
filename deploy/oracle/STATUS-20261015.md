# ACR Rally Club — migracja na Oracle, 15.10.2026

Strona i baza danych działają na Oracle Cloud we Frankfurcie. Publiczny adres:
https://acr.projectsimracing.pl/ — rekord A wskazuje na 92.5.82.116.
Wersja aplikacji i launchera pozostaje 0.2.16; przeniesienie infrastruktury nie
zmienia zasad rajdów ani wymaga ponownej instalacji launchera używającego tej domeny.

## Co wykonano

- Przygotowano jedną maszynę Oracle Linux 9.8 ARM: 1 OCPU, 2 GB RAM, 50 GB.
  Nieużywaną maszynę testową usunięto razem z dyskiem startowym.
- Aplikacja, Caddy i PostgreSQL 18 działają jako kontenery Podman nadzorowane
  przez systemd/Quadlet, z autostartem i ponawianiem po awarii procesu.
- Porty aplikacji i bazy nie są publiczne; PostgreSQL jest dostępny wyłącznie
  w prywatnej sieci kontenerów. Aplikacja używa odrębnej roli bez uprawnień
  administratora bazy. SELinux pozostaje Enforcing.
- Zachowano konfigurację Steam, sesje klubowe, adres i zabezpieczenia panelu,
  dotychczasowe hasło/klucz administratora oraz adres pobierania launchera.
  Sekrety mają uprawnienia 0600 i nie trafiły do repozytorium.
- Zatrzymano Render i wyłączono jego automatyczne wdrożenia przed końcowym
  eksportem bazy. Oracle jest jedynym aktywnym serwerem zapisującym wyniki.
- Po zatrzymaniu Render wykonano świeży eksport Neon, odtworzono go w Oracle
  i porównano zawartość wszystkich 31 tabel oraz stan sekwencji. Wszystkie były
  identyczne; zachowano 12 wyników, kary i pozostałe dane.
- Zachowano oryginalną bazę Neon i wcześniejsze kopie. Kod sprzed migracji:
  gałąź `rollback/pre-oracle-20261015`, commit
  `760a085795329d1d2372cb6abb9ac1db7ad56e49`.

## Weryfikacja

- 276 testów serwera na rzeczywistym Oracle Linux ARM64; CI z obrazami AMD64
  i ARM64 oraz kontrolami SQLite/PostgreSQL, hostingu i Chromium przeszedł
  przed przełączeniem.
- Publiczne HTTPS z poprawną walidacją certyfikatu: strona główna, healthz,
  lista rajdów, sezony, launcher i instrukcja zwróciły HTTP 200.
- Bez uwierzytelnienia panel i API administratora zwracają 401. Sprawdzono
  dotychczasowe hasło bramy, logowanie kluczem aplikacji, odczyt danych panelu
  i wylogowanie. Publiczna strona została również otwarta w przeglądarce.
- Kontrola środowiska działającego procesu potwierdziła host bazy `database`
  w prywatnej sieci Oracle, a nie Neon. Wszystkie trzy usługi były aktywne.

Logowanie Steam rzeczywistego gracza, RUN, przejazd, wznowienie i przesłanie
wyniku z gry Windows wymagają końcowej próby użytkownika. Testy HTTP nie są
przedstawiane jako wykonany przejazd gry.

## Kopie i odzyskiwanie

Prywatny bucket Object Storage `acr-migration-backups` zawiera pełne archiwa:

- Przed migracją: `before-oracle-20261015.tar.gz`, 133338 bajtów,
  SHA256 `7bb207bc17958509c53941a96d45e39166aa402807b4af3bd844e13e366d6c5d`.
  Eksport odtworzono w oddzielnym PostgreSQL 18 i sprawdzono pobrane archiwum.
- Po przełączeniu: `cutover/20261015T105547Z-f7a01506bc564df1a0db3022952bd15a.tar.gz`,
  135896 bajtów, SHA256
  `0aae23131fac41c97f83d215e0c3d3390a4eaf690274415b3d4520406a0b9c27`.
  Zawiera bazę, konfigurację aplikacji, Caddy i PostgreSQL oraz jednostki usług.
  Przed wysłaniem sprawdzono katalog eksportu; pobrane archiwum porównano SHA256.

Archiwa zawierają sekrety: nie publikować, nie przesyłać w zgłoszeniach GitHub.
Klucz API właściciela OCI nie został wysłany na maszynę ani do archiwów.
Maszyna ma tylko możliwość tworzenia nowych obiektów `cutover/*` w tym jednym
buckecie przez tożsamość instancji; nie może czytać, nadpisywać ani usuwać kopii.
Skrypt `backup-once.sh` pozostaje opcją ręczną. Po migracji włączono oddzielny
harmonogram: baza co 6 godzin, pełna kopia codziennie i próbne odtworzenie co
tydzień. Historia wygasa po 2 dniach dla bazy i 7 dniach dla pełnych archiwów;
ostatnie poprawne kopie pozostają bezterminowo. Szczegóły: `scheduled/README.md`.
Nie włączono kopii na Dysku Google.

**Neon po migracji jest zamrożoną kopią, nie aktualną bazą.** Przy wycofaniu
należy zatrzymać Oracle i jego autostart, przenieść najnowsze dane z Oracle do
bazy docelowej, a dopiero potem uruchomić Render i zmienić DNS. Samo wznowienie
starego Render/Neon utraciłoby wyniki zapisane po przełączeniu.

## Co pozostaje właścicielowi i graczowi

1. Wykonać rzeczywiste logowanie Steam i krótki test w grze: RUN, start OS,
   wynik i ewentualne wznowienie zgodnie z zasadami rajdu.
2. Zachować dostęp do konta Oracle i kopii. Cykliczne kopie z krótką retencją są już
   włączone i sprawdzone odtworzeniem; osobne archiwa migracyjne pozostawiono.
3. Nie uruchamiać starego Render z jego obecną konfiguracją. Starsze launchery
   skonfigurowane bezpośrednio na adres onrender.com wymagają przestawienia
   na domenę klubu lub ponownej instalacji z aktualnej strony.
4. Po potwierdzeniu działania można osobno zdecydować o likwidacji zasobów
   Render/Neon. Nie usunięto ich automatycznie.

Nie wdrożono sztucznego obciążania maszyny ani płatnych aktualizacji konta.
Always Free nadal podlega zasadom odzyskiwania mało używanych instancji Oracle.
Konfiguracja i kopie ułatwiają odzyskanie, lecz nie gwarantują pracy bez przerw.
