# ACR Rally Club — stan migracji na Oracle, 15.10.2026

Przygotowanie serwera zakończone; przełączenie produkcji oczekuje na uzgodnienie
DNS z właścicielem domeny. Klub nadal działa na Render i Neon. Wersja aplikacji
i launchera pozostaje 0.2.16.

## Wykonane prace

- Uzyskano i sprawdzono dostęp do OCI przez podpisane REST API w regionie Frankfurt.
- Utworzono osobny compartment, sieć, podsieć i reguły zapory. Publiczne porty:
  HTTP/HTTPS; SSH ograniczony do pojedynczego adresu operatora. Port aplikacji
  i PostgreSQL nie są publiczne.
- Pozostaje jedna maszyna Oracle Linux 9.8 ARM: 1 OCPU, 2 GB RAM, dysk 50 GB,
  IP 92.5.82.116. Nieużywane testowe Ubuntu usunięto razem z dyskiem startowym.
- Sprawdzono zarządzanie przez OCI Run Command. Grupa dynamiczna obejmuje tylko
  wydzielony compartment; polityka agenta pozwala wykonywać polecenia tylko dla
  własnej instancji. SELinux pozostał w trybie Enforcing.
- Zainstalowano Podman z repozytoriów Oracle i zbudowano niezmienną wersję kodu
  760a085795329d1d2372cb6abb9ac1db7ad56e49.
- Wyeksportowano konfigurację Render, przesłano ją zaszyfrowaną do Oracle,
  przygotowano pliki 0600 oraz jednostki systemd/Quadlet. Nie uruchomiono drugiego
  serwera zapisującego dane do produkcyjnej bazy.
- Zabezpieczono kod w gałęzi rollback/pre-oracle-20261015. Pełny eksport bazy,
  konfiguracja i pliki uruchomieniowe znajdują się w prywatnym archiwum opisanym
  w MIGRATION.md. Nie usunięto wcześniejszych kopii w Neon.

## Sprawdzenie działania

- 276 testów serwera przeszło na rzeczywistym Oracle Linux ARM64.
- Testowa aplikacja na odrębnej SQLite: HTTP 200 dla zdrowia, strony głównej,
  sezonów, launchera i instrukcji; wejście bez sekretu bramy odrzucone 403.
- Po zakończeniu polecenia administracyjnego usługi pod nadzorem Quadlet/systemd
  pozostały aktywne. Natywny Caddy zwrócił 200 dla kontroli zdrowia i 401 dla
  rzeczywistego adresu panelu oraz API administratora bez uwierzytelnienia.
- Generator Quadlet zakończył walidację bez błędów.
- Pełny eksport PostgreSQL odtworzono bez błędów w oddzielnym PostgreSQL 18
  (12 wyników); archiwum pobrano i sprawdzono sumę kontrolną. Potwierdzono zgodność
  konfiguracji oraz zachowanie dotychczasowego hasła administratora.
- Wcześniejszy CI: natywne obrazy AMD64/ARM64 oraz SQLite, PostgreSQL, hosting
  i Chromium przeszły pomyślnie.

Publiczny certyfikat, logowanie Steam na docelowym serwerze i rzeczywisty przejazd
w grze wymagają sprawdzenia po zmianie DNS. Nie są tutaj przedstawiane jako
wykonane testy produkcyjne.

## Dalsze kroki

1. Właściciel domeny zmniejsza TTL istniejącego CNAME acr do 300, pozostawiając
   wskazanie na Render. Trzeba odczekać dotychczasowy TTL (do godziny).
2. Uzgodnić krótkie okno przełączenia. Odświeżyć kopię bazy i sprawdzić, czy nie
   trwają przejazdy ani wysyłanie wyników.
3. W tym oknie właściciel zastępuje CNAME rekordem A: acr → 92.5.82.116.
   Zatrzymać zapisujący proces Render przed uruchomieniem Oracle; sprawdzić TLS,
   logowanie, RUN, wznowienie i wyniki. Baza na tym etapie pozostaje w Neon.
4. Zachować możliwość wycofania: przed ponownym uruchomieniem Render zatrzymać
   Oracle i wyłączyć jego autostart. W razie potrzeby przywrócić poprzedni DNS.

Nie wdrożono sztucznego obciążania maszyny ani gwarancji wyłączenia odzyskiwania
nieaktywnych instancji przez Oracle. Darmowe zasoby nadal podlegają zasadom OCI.
Nie wdrożono cyklicznego wysyłania kopii na Dysk Google.
